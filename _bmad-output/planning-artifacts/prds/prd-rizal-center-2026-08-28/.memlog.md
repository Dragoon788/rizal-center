- (event) Update intent: tighten existing prd.md in place at project root; not relocated to _bmad-output
- (decision) V1 reframed from public launch to structural prototype demoed to Rizal Center staff and admin while current WordPress site stays live
- (decision) Demo target end of September 2026 adopted as the forcing function; no prior deadline existed
- (insight) Volunteers already do double work today: events maintained on the website AND posted to Facebook. Present-tense validated pain, absent from PRD v0.2
- (decision) Promote double work to primary problem statement; demote social aggregation to a future option so no Meta API sits on the prototype critical path
- (decision) Open Graph share cards promoted from SEO NFR to core demo deliverable - attacks double work with no Meta API dependency
- (decision) Scope model is breadth in schema, depth in pages: model every content type, build polished pages only for homepage, events, announcements, one topic page
- (decision) Newsletter is modeled in schema but no page built in V1; reverses earlier suggestion to cut it since newsletter archive is migration-important
- (decision) Resources removed from direct-arrival pages: resource is a Sanity object inside resourceList and cannot have a URL. Schema was right, PRD v0.2 was wrong. Per-resource pages would be thin content harming the SEO goal
- (decision) Announcements get their own pages and therefore need a slug, plus an explicit active/expiry concept so homepage can show current ones. announcement.ts currently has startDate, endDate and active commented out
- (decision) SEO metadata derived from existing content by default; author-controlled override fields only on Topics and Homepage. Avoid meta fields on every type that 1-2 volunteers will leave blank
- (decision) Authors renamed to People to match the profile schema; someone can be a board member without authoring anything
- (decision) Topic creation restricted to the admin by convention, not enforced permissions, given a 3-person editorial team
- (decision) Topic assignment made a prominent primary step in the editorial flow; it is currently buried in a collapsed Advanced and Admin fieldset in event.ts which would silently break Topic pages
- (decision) Content migration is demo-critical not deferred: migrate newsletter archive, events, posts. Skip past events, media archives, stale content. A demo on lorem ipsum will not persuade staff
- (decision) SEO redirects and URL preservation moved out of V1 into an explicit pre-launch gate since the current site stays live
- (assumption) Demo hosting decoupled from target hosting: use a free preview deploy for the September demo, validate Cloudflare plus OpenNext after. Protects the deadline; Next.js stays portable
- (decision) A generic page type added to the content model so the About page in the IA is buildable by an editor
- (change) prd.md rewritten to v0.3: prototype framing, double-work problem promoted to primary, aggregation demoted to future option, scope split into modeled vs built with an explicit cut order, demo-outcome success metrics with counter-metrics, migration and pre-launch gates and a 7-item risk register added
- (event) PRD v0.3 draft complete; architecture hardening is the next pass
